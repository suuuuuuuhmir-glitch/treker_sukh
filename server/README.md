# Аккаунты МишкаФит

Аккаунт нужен, чтобы прогресс сохранялся в облаке сам: без файлов и кнопок,
и на телефоне, и на планшете.

Как это устроено:

- Трекер по-прежнему хранит всё на телефоне и работает без интернета.
- Если человек вошёл в аккаунт, изменения уходят в облако через 15 секунд
  после последней правки или сразу, когда приложение сворачивают.
  При открытии трекер сверяется с облаком.
- Если два устройства меняли данные без связи, записи с обоих сохраняются.
- Ответы о здоровье и фото остаются только на телефоне.

Где хранить, выбирается одной настройкой `CLOUD` в `tracker.html`:

```js
// сейчас: Google Firebase
const CLOUD = window.MF_CLOUD || {provider:'firebase', apiKey:'…', projectId:'…'};
// запасной вариант: своя функция в Яндекс Облаке (данные в России)
const CLOUD = window.MF_CLOUD || {provider:'yandex', url:'https://functions.yandexcloud.net/…'};
```

Пока настройка пустая, блок «Аккаунт» в приложении не показывается.
При смене варианта люди один раз входят заново, данные с телефона
уходят в новое облако.

## Вариант 1. Google Firebase (сейчас)

Бесплатно, карта не нужна. В бесплатном тарифе Spark каждый день:
50 000 чтений и 20 000 записей, хранилище 1 ГБ. Трекер пишет не чаще
раза в 15 секунд, так что этого хватает на сотни людей в день.

Пароли хранит Google, мы их не видим. Есть «Забыли пароль?»: Google
сам присылает письмо на русском.

### Как настроить (минут 10)

1. Открой [console.firebase.google.com](https://console.firebase.google.com)
   и войди своим Google-аккаунтом.
2. **Create a project** (Создать проект). Имя: `mishkafit`. Google Analytics
   можно выключить, он не нужен. Нажми **Create project**.
3. **Вход по почте.** В меню слева **Build → Authentication**
   (Аутентификация) → **Get started**. На вкладке **Sign-in method**
   выбери **Email/Password**, включи первый переключатель (Enable),
   нажми **Save**.
4. **База для данных.** В меню **Build → Firestore Database** →
   **Create database**.
   - Если спросит про редакцию, выбери **Standard**.
   - Location: `europe-north1 (Finland)` или другой европейский регион,
     ближе к России. Поменять потом нельзя.
   - Режим: **Start in production mode**. Нажми **Create**.
5. **Правила доступа.** В Firestore открой вкладку **Rules**, сотри всё,
   что там написано, и вставь текст из файла [firestore.rules](firestore.rules).
   Нажми **Publish**. Эти правила разрешают каждому видеть и менять только
   свои данные.
6. **Ключ для сайта.** Нажми шестерёнку рядом с **Project Overview** →
   **Project settings**. Внизу, в блоке **Your apps**, нажми значок `</>`
   (Web). Имя: `МишкаФит`. Галочку Firebase Hosting **не ставь**.
   Нажми **Register app**.
7. Появится кусок кода `firebaseConfig`. Пришли Claude две строчки из него:
   `apiKey` и `projectId`. Они не секретные: этот ключ и так виден всем
   в коде сайта, а данные защищают правила из шага 5.
8. Необязательно: в **Project settings → General** поле **Public-facing name**
   впиши `МишкаФит`. Это имя будет в письме для сброса пароля.

После этого Claude впишет ключ в трекер, проверит вход и сохранение,
и в приложении появится кнопка аккаунта.

Письма для сброса пароля приходят с адреса `noreply@<проект>.firebaseapp.com`
и иногда попадают в «Спам». Трекер подсказывает это человеку.

### Ограничения

- Данные лежат на серверах Google за границей. Для большого продукта
  в России по закону о персональных данных (152-ФЗ) их нужно будет
  перенести в Россию: это вариант 2.
- У некоторых операторов в России сервисы Google иногда работают с перебоями.
  Трекер от этого не ломается: всё сохраняется на телефоне и уходит
  в облако, когда связь появится.
- Один человек — одна запись в базе, до 1 МБ. Этого хватает примерно
  на пару лет активных записей; когда понадобится, данные можно сжимать.

## Вариант 2. Яндекс Облако (запасной, данные в России)

Одна функция ([index.js](index.js)) и закрытое хранилище файлов. Пока
пользователей немного, это бесплатно: каждый месяц Яндекс не берёт денег
за первый 1 000 000 вызовов функции и первый 1 ГБ хранилища. Нужна карта.
Пароли хранятся только в виде хеша (scrypt). Сброса пароля письмом пока нет.

### 1. Аккаунт в Яндекс Облаке

1. Открой [console.yandex.cloud](https://console.yandex.cloud) и войди через Яндекс ID.
2. Создай платёжный аккаунт: физическое лицо, привяжи карту. В пределах
   бесплатного объёма деньги не списываются.
3. Облако и каталог `default` создадутся сами, дальше всё делаем в нём.

### 2. Хранилище для данных

1. В меню слева выбери **Object Storage** → **Создать бакет**.
2. Имя: например `mishkafit-data` (если занято, добавь цифры).
3. Доступ на чтение объектов, к списку объектов и к настройкам: **Ограниченный**.
4. Класс хранилища: **Стандартное**. Нажми **Создать бакет**.

### 3. Сервисный аккаунт

1. В меню выбери **Identity and Access Management** → **Сервисные аккаунты** → **Создать сервисный аккаунт**.
2. Имя: `mishkafit-api`. Роль: `storage.editor`. Нажми **Создать**.

### 4. Функция

1. В меню выбери **Cloud Functions** → **Создать функцию**, имя `mishkafit-api`.
2. Выбери среду выполнения **Node.js 22** (`nodejs22`), без примера кода.
3. Способ: **ZIP-архив** с одним файлом [index.js](index.js) или **Редактор
   кода**: создай файл `index.js` и вставь в него весь текст из [index.js](index.js).
4. Заполни поля:
   - Точка входа: `index.handler`
   - Таймаут: `10` секунд
   - Память: `128 МБ`
   - Сервисный аккаунт: `mishkafit-api`
   - Переменные окружения:
     `BUCKET` = имя бакета из шага 2,
     `ORIGINS` = `https://mishkafit.ru`
5. Нажми **Сохранить изменения**.
6. На вкладке **Обзор** включи **Публичная функция**.
7. Скопируй **Ссылку для вызова** (вида `https://functions.yandexcloud.net/d4e...`)
   и пришли её Claude. Ссылка не секретная, её можно присылать.

### 5. Необязательно: предупреждение о расходах

**Биллинг** → **Бюджеты** → создай бюджет на 100 ₽ с уведомлением на почту.
Если когда-нибудь пользователей станет много и бесплатный объём закончится,
придёт письмо.

### Проверка без облака

`index.js` можно запускать локально: нужен Node.js 22, заглушка хранилища
по `STORAGE_URL` и передача `context.token.access_token` в обработчик.
